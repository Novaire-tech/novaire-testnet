## What it is

`packages/bindings/` contains one auto-generated TypeScript package per contract, produced by the Stellar CLI:

```bash
stellar contract bindings typescript \
  --id <contract-id> \
  --network <network> \
  --output-dir ./packages/bindings/<contract-name> \
  --overwrite
```

This is run automatically as part of `scripts/deploy.ts` and `scripts/deploy_xlm_epoch.ts` after each deploy, so the bindings always reflect the currently-deployed contract's actual interface.

## Packages

`factory`, `sy_wrapper`, `vault`, `tokenizer`, `pt_token`, `yt_token`, `marketplace`, `intent_engine`, `rollover` — each with its own `package.json` (`version: 0.0.0`), depending on `@stellar/stellar-sdk@^14.5.0`.

<Note>
  These packages are **not** wired in as npm workspace dependencies of `apps/web` — they're consumed via relative import paths (e.g. `../../../../packages/bindings/marketplace/src/index`), not a package name. Keep this in mind if you're used to workspace-resolved imports.
</Note>

## Shape of a generated client

Each `src/index.ts` exports:

- `networks` — hardcoded `contractId` per network, e.g.:
  ```ts
  export const networks = {
    testnet: {
      networkPassphrase: "Test SDF Network ; September 2015",
      contractId: "CCCMNVS2O5NXTMUQPOQEHO7NOYN5NBOYIZXYB4BXWZ6TKR43GDYOKD4V",
    },
  };
  ```
- Generated types (`DataKey`, per-contract metadata interfaces, error enums).
- A `Client` class extending `ContractClient`, with one method per contract entry point, each returning an `AssembledTransaction`:
  ```ts
  deposit: (
    { depositor, amount }: { depositor: string; amount: i128 },
    options?: MethodOptions
  ) => Promise<AssembledTransaction<Result<i128>>>;

  metadata: (options?: MethodOptions) => Promise<AssembledTransaction<Result<VaultMetadata>>>;
  ```

## Using a binding

```ts
import { Client as VaultClient } from "../../packages/bindings/vault/src/index";

const vault = new VaultClient({
  contractId: "<deployed-vault-address>",
  networkPassphrase: "Test SDF Network ; September 2015",
  rpcUrl: process.env.NEXT_PUBLIC_RPC_URL,
});

const tx = await vault.deposit({ depositor: userAddress, amount: 100_0000000n });
const result = await tx.signAndSend();
```

`apps/web` consumes these bindings directly in `src/hooks/useTrade.ts`, `src/components/modals/MintModal.tsx`, `src/services/{portfolioService,protocolService,walletService,yieldService}.ts`. `apps/indexer` does **not** use `packages/bindings` — it talks to `@stellar/stellar-sdk` directly.
