---
title: "Core Concepts"
description: "The vocabulary you need before reading the architecture and protocol sections"
---

<Accordion title="SY (Standardized Yield)">
  A wrapped representation of a deposit that has been supplied into a yield source (currently Blend Capital). `sy_wrapper` mints SY shares against deposits and tracks an internal exchange rate, scaled by `EXCHANGE_RATE_SCALAR = 1_000_000_000` (1e9 — not WAD/1e18). See [SY](/protocol/sy).
</Accordion>

<Accordion title="PT (Principal Token)">
  A standalone Soroban token contract (`pt_token`), minted 1:1 against SY shares by `tokenizer`. Redeemable 1:1 for the underlying once its epoch is settled. Transfers are never paused, even if the contract is otherwise paused — an explicit design decision to preserve secondary-market liquidity. See [PT](/protocol/pt).
</Accordion>

<Accordion title="YT (Yield Token)">
  A standalone Soroban token contract (`yt_token`), minted 1:1 alongside PT. Entitled to the yield generated by the underlying position between mint and maturity, tracked via an internal `YieldIndex` / `UserYieldIndex` accumulator scaled by `YIELD_SCALAR = 1_000_000_000`. See [YT](/protocol/yt).
</Accordion>

<Accordion title="Epoch">
  A fixed-term market with its own `maturity_ledger`, its own PT/YT tokens, and its own AMM instance — deployed and wired together in one call by `factory.deploy_epoch()`. Epochs move through a state machine: `Active → Matured → Settled → Archived`, tracked by `maturity_engine`.
</Accordion>

<Accordion title="AMM / Marketplace">
  `marketplace` implements a YieldSpace-style time-decaying invariant, `k = A_pool*(x+y) + x*y`, where `A_pool` grows from near-zero at epoch genesis toward a large value at maturity — interpolating from constant-product-like behavior early in the epoch to constant-sum (1:1) behavior near maturity. YT is priced off the same curve via a virtual-sale simulation, not a separate pool. See [AMM](/protocol/amm).
</Accordion>

<Accordion title="Implied rate / TWAP">
  The discount at which PT trades against the underlying implies a fixed rate for the remaining term. `marketplace` tracks a time-weighted average of this rate (`ImpliedRateTwap`) with a staleness guard (`MAX_TWAP_AGE_LEDGERS = 200`) so downstream contracts (like `intent_engine`) can gate on a non-stale, flash-loan-resistant rate.
</Accordion>

<Accordion title="Vault">
  A thin share-accounting pass-through between users/`tokenizer` and `sy_wrapper`. Holds no yield logic of its own — it exists to separate custody/accounting from the yield-bearing mechanics in `sy_wrapper`. See [Vault](/architecture/contract-architecture).
</Accordion>

<Accordion title="Intent Engine">
  Composes multi-step flows (deposit → mint PT/YT → swap) into a single transaction, so a user expresses a strategy ("fixed yield" or "yield speculation") instead of orchestrating each contract call manually. See [Transaction Lifecycle](/architecture/transaction-lifecycle).
</Accordion>

<Accordion title="Rollover">
  Automates redeeming a matured PT position and reinvesting the proceeds into the next linked epoch via `intent_engine`, with a keeper-gated grace period followed by permissionless execution for liveness.
</Accordion>

<Accordion title="bRate / AUM">
  Terms associated with Blend Capital's own reserve accounting. Novaire's `sy_wrapper` does **not** compute Blend's real `b_rate` — it sums Blend's reported `supply` value 1:1 as an approximation of underlying-equivalent value, an explicitly documented simplification. See [Blend Integration](/protocol/blend-integration).
</Accordion>
