## What YT is

`yt_token` is a standalone, custom Soroban token contract (`VERSION=2` in its own code), minted 1:1 alongside PT by `tokenizer`. It entitles the holder to the yield generated by the underlying position between mint time and maturity.

- `name()`/`symbol()` = "nYT", `decimals()` = 7.
- Mint/burn restricted to `tokenizer.require_auth()`, same pattern as `pt_token`.

## Yield accrual mechanism

YT tracks yield via a reward-per-share accumulator, scaled by `YIELD_SCALAR = 1_000_000_000` (1e9):

- `YieldIndex` — the global cumulative index, updated by `tokenizer`/`update_yield_index`.
- `UserYieldIndex(Address)` — the index value at the user's last checkpoint.
- `AccruedYield(Address)` — yield already checkpointed but not yet claimed.

`checkpoint_user` accrues `(YieldIndex - UserYieldIndex[user]) * balance / YIELD_SCALAR` into `AccruedYield[user]`, then advances `UserYieldIndex[user]` — the standard reward-per-share pattern, run on every transfer/mint/burn so balances always reflect a consistent snapshot.

## The reentrancy workaround

`yt_token.refresh_index_locally()` pulls a live surplus snapshot from `tokenizer` to update its own index. Soroban does not allow a contract to call back into itself further up the same call stack, so this pull-based refresh is explicitly engineered around that restriction rather than having `tokenizer` push updates directly mid-call (documented in-code).

## Transfers and yield

Unlike `pt_token`, YT transfers **do** interact with the pause flag normally, and accrued-but-unclaimed yield is explicitly locked to the sender at transfer time (`test_transfer_locks_accrued_yield_to_sender`) — selling YT does not carry already-accrued, unclaimed yield to the buyer.

## Claiming yield

`tokenizer.claim_yield(user) -> i128` checkpoints the user's accrued yield and pays it out. This can be called any time before or after maturity; `test_is_expired_true_after_maturity` and `test_transfer_still_works_after_maturity` confirm YT remains a live, transferable, claimable token after its epoch has matured — it isn't burned or frozen at maturity, only capped in how much future yield it can accrue.

## YT and the AMM

There is no separate YT liquidity curve. `marketplace` derives a YT price by simulating a "virtual sale" against the same PT/underlying curve that prices PT — see [AMM](/protocol/amm) for the exact mechanism (`solve_yt_out_for_underlying_in`, `compute_yt_sell_proceeds`).
