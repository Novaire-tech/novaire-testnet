```text
├── factory/src/test.rs
├── sy_wrapper/src/test.rs, audit_tests.rs
├── vault/src/lib.rs (inline #[cfg(test)])
├── maturity_engine/src/lib.rs (inline)
├── tokenizer/tokenizer/src/lib.rs (inline)
├── tokenizer/pt_token/src/test.rs
├── tokenizer/yt_token/src/test.rs
├── marketplace/src/lib.rs (inline, incl. proptest)
├── intent_engine/src/lib.rs (inline)

└── integration_tests/src/
    ├── e2e.rs, fuzz.rs, simulation.rs, stress.rs

    ├── m1_production_bootstrap.rs, m1_regression.rs
    ├── m2_regression.rs, m3_regression.rs, m5_regression.rs
    ├── invariants.rs, mock_blend_pool.rs, framework.rs
```

## Running the suite

```bash
cd contracts && cargo test
```

Per-crate: `cargo test -p sy_wrapper`, `cargo test -p marketplace`, etc. There is no documented CI workflow in this repository — `cargo test` is run manually per `README.md`'s Contributing section. See [Testing → Setup](/developers/testing) for the developer workflow.

## What the M1–M5 regression suites cover

These names come directly from `contracts/integration_tests/src/` and correspond to historically-identified issues, now covered by regression tests:

- **M1** — YT/PT pricing symmetry and exploit-reproduction scenarios (`test_m1_sell_yt_matches_complement_price`, `test_m1_exploit_reproduction_at_epoch_start`, `test_m1_repeat_attack`, `test_m1_large_capital_attack`).
- **M2** — late-minter historical yield credit correctness (`test_m2_late_mint`, `test_m2_no_trapped_shares`, `test_m2_minimal_mint_rounding`).
- **M3** — settlement correctness under adversarial timing (`test_m3_attacker_early_settlement`, `test_m3_h5_clamp_preserved`, `test_m3_original_attack_prevented`).
- **M5** — liquidity/donation-attack invariants (`test_m5_donation_attack_impossible`, `test_m5_locked_liquidity_permanent`).

See dedicated pages for [Unit Tests](/testing/unit-tests), [Integration Tests](/testing/integration-tests), [AMM Tests](/testing/amm-tests), and [Blend Testing](/testing/blend-testing).
